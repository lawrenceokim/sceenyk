Acceptance preserves the image and pauses before storyboard. Rejection only deletes the fenced candidate, clears active/review state and returns to **Generate Location**. ## Planning inputs and provider

`ugc_location_scene` reads the owned draft's current **saved** scene description, Character/Product reference names, available completed reference-analysis observations, visual style, tone, creation/UGC type, duration and aspect ratio. It preserves the job's supported narration configuration. A short nonempty description is sufficient: OpenAI infers a coherent filming environment using the video type and product context. Names are untrusted labels; uncertain observations remain uncertain. The plan contains name, environment, lighting/atmosphere, visual style, camera framing and image-generation prompt.

The database verifies that approved job source IDs still refer to the active owned Character/Product uploads with the frozen ETags. Replacing/detaching a source image requires its own approved reference workflow; old approvals never silently authorize a replacement upload. Saved label/scene/settings changes with the same approved sources can replan without altering Character/Product work. Save Studio edits before generating/regenerating; unsaved browser fields are not workflow authority.

The existing OpenAI Responses structured-output adapter creates the private plan. Its checkpoint atomically saves the plan/receipt and queues one image candidate. The same local worker processes that image on its next poll; no browser round trip or approval is needed. Source Character/Product images are not sent to Location image generation. The prompt enforces the selected visual style, consistent environment/lighting and staging space while excluding people/main Character/featured Product, hero props, packaging, logos and text. Visual compliance remains manual, not an automatic semantic rejection.

Safe phase/database/HTTP/transport codes are retained in current state and append-only diagnostic history across retries, without raw messages, credentials, URLs or bytes.

Retry saving obtains a scoped storage-only lease and checks the existing R2 object first, then the exact private local file. Unknown submission outcome still requires reconciliation; it is never automatically replayed. Restarted existing-image work uses the same provider-free recovery helper. Local files are retained through saving failures/approval; only explicit rejection cleans that candidate file. Output lost before any durable bytes were written remains unrecoverable from the old request receipt alone.
