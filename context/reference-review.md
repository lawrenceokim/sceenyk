## Private preview contract

`POST /api/ugc/reference-review` authenticates the Clerk session, reads the existing app_users identity, verifies a draft Project and job owner, validates the requested group/version/view and resolves the canonical asset server-side. Neither browser-provided R2 keys/URLs nor arbitrary asset IDs are accepted. The frozen job source is used, including an owned historical source detached from the current draft; a later replacement upload is never substituted. Original identity/role/upload/ETag/size/MIME/reference ID are checked. Generated descriptors must match the canonical owned job/sheet path and asset type.

`action=preview` returns a **120-second signed same-origin URL**. Direct R2 presigns expose object keys in their paths, so the browser receives an authenticated application capability instead. HMAC-SHA256 uses the existing private database secret with a dedicated purpose prefix; no new environment variable. Payload contains only application scope, logical view, owner binding, version, fingerprint and expiry, never provider IDs, R2 keys/URLs or credentials. URLs are transient component state, never database/template metadata. No capability/body is logged.

`GET /api/ugc/reference-review/image` verifies the signature in constant time, checks expiry, authenticates/re-authorizes the session and same owner/Project/job again, rechecks review version and exact asset fingerprint, then reads private R2 with If-Match and bounded cancellation/timeouts. A copied URL is insufficient for another account or an unauthenticated request. Original images are decoded/oriented, fitted inside 2048px without cropping, metadata-stripped and returned as ephemeral PNG; generated PNGs stream from their saved immutable descriptor. No file is modified/stored. Responses are private/no-store with no CDN cache, nosniff, no-referrer and same-origin resource policy. Native images avoid Next image-optimizer caching of private capabilities.

Thumbnails issue URLs only when visible (mounted-image fallback when IntersectionObserver is unavailable); the lightbox obtains its own fresh capability. Expired/unavailable images offer an explicit retry/reopen, not continuous renewal. Mutation/preview-issuance POSTs require the same Origin and bounded JSON input. Every endpoint enforces authorization, regardless of UI controls.

## Persistence and state

Manual-only [046](../supabase/migrations/20261024004600_ugc_reference_reviews.sql), after 045, adds private `ugc_reference_reviews` and `ugc_reference_regeneration_requests`. Existing Character/Product sheet documents remain the immutable source of generated-asset truth. These new records hold human review decisions/replacement intent, not a second generation-job queue. Missing historical review rows derive **ready_for_review**, never approved, when completed sheets exist. Reads create no rows or backfills.

A review root pins owner/Project/job, reference type, exact Character or Product sheet ID and generation sheet version. Initial review/composed version is 1. Explicit approval persists approved_at, approved_by and approved_version for the current version. Approval requires a completed sheet and every required view, no pending replacement and current composition version. Owner checks, job-first locking, expected-version comparison, RLS/no browser grants, service-only RPCs and append-only existing job events enforce the boundary. Repeated approval is idempotent. No automatic approval on migration, generation completion, reopen or template adoption.

States project from existing job/sheet state plus review decisions: pending_generation, ready_for_review, approved, regeneration_requested, regenerating, failed. There is no parallel editable status flag competing with sheet/provider checkpoints. The safe progress DTO explicitly projects only names, logical labels, availability, effective states/versions, approval time and gate flags; keys, asset/provider IDs, private documents and fingerprints stay server-only.

## Individual replacement infrastructure

`ugc_request_reference_regeneration` accepts only Front/Back/Face for Character or Primary/Angled/Detail for Product. It locks the owned paused/failed job and review root, checks the expected version/existing view, writes an idempotent request UUID/previous asset ID/requested-by/version, increments only that group's review version, clears its approval and atomically appends a fixed safe event. Other groups/views and all source/generated files, original provider request IDs and checkpoints remain untouched. One unresolved request per view prevents duplicate intent. A lost response can recover using the same request UUID.

Version greater than composed_version, or any unresolved request, invalidates the **effective** final sheet. The historical sheet remains visible with a stale/rebuild warning; it is never treated as current or approvable. No whole-sheet generation, automatic paid view request, job enqueue/retry/resume, R2 overwrite or provider call is performed by this action.

`referenceReplacementPlan` is a read-only version-1 contract for a later explicitly authorized executor: requested view identities, preserved effective successful views, target version, composition requirement and a fresh immutable `reference-review-v1/{reviewId}/v{version}` storage namespace. Request replacement descriptors and a root composed-asset descriptor can represent future outputs. Resolved descriptors must validate their exact owned path/type/schema; completed replacement views are reused as composition inputs instead of old base views. Thus a future worker can replace only requested views and recompose using unchanged/previously successful assets. The original v1 documents/files stay immutable.

**Paid replacement execution and publication are deferred.** No dispatch/claim/complete/fail RPC for replacement execution is exposed in 6.5. The later executor must add claim-fenced lifecycle/publication, persist each validated replacement immediately, compose only after required replacements are ready, atomically publish the new composed descriptor/version, then require a new human approval. This milestone records intent and exposes the plan; it does not pretend the old M5/M6 worker already processes replacement requests. Existing workers are gated from consuming invalidated references. Failed/active replacement state schemas and progress projection are prepared, but no fake worker activity is written.

## Workflow gates and polling

Database Product resume/prepare wrappers require a current Character approval. Old implementations lose service-role execute grants, closing direct bypasses. A job-update trigger fences reference claims: pending replacements or missing Character approval return the job to its existing development pause without spending a claim. The trigger shares the same job lock as review mutations, which reject running jobs. Existing schema/graph still make Location a queued-only non-runnable boundary. `ugc_location_references_approved` requires current approvals for **both** groups; future downstream stage transitions also enforce this predicate. There is no Location handler/resume/implementation.

Approval/request actions do not update or resume the job. The shared read model can identify blocked queued work without continuous polling or rewriting historical jobs. Active generation/actual regenerating state polls; ready/approved/requested pauses and failed/completed/cancelled states stop. Check status and visible tab return retain the existing one-off observation behavior. A future server-confirmed resume uses the existing refreshAfterResume path; no new polling owner or route action is added.
