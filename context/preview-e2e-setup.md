## Confirmed audit and changes

- Both PayPal credit and Marketplace order adapters previously built return/cancel URLs from one fixed `PAYPAL_RETURN_ORIGIN`. Local currently points to loopback. Web checkout now resolves the initiating request on the server and permits only the configured origin and exact Vercel-assigned deployment/branch domains. Unrelated `vercel.app` hosts, credentials, paths, query/fragment payloads and deployed loopback are rejected. Browser input cannot supply an arbitrary redirect. Existing return paths/query handling remain; Next's existing redirects lead to `/credits` and `/marketplace/purchases`.
- `PAYPAL_RETURN_ORIGIN` remains the stable administrator origin for webhook/payout readiness. A browser checkout origin never replaces that webhook binding. Local checkout preserves its configured port; Preview metadata uses its deployment URL; Production metadata prefers the configured canonical origin, then the platform production domain. No new application variable was introduced. Automatic domains come from Vercel's trusted server env, not arbitrary forwarded hosts.
- Original PayPal order IDs, idempotency keys, owned purchase checks, amount/currency/custom/invoice verification, capture verification, signature postback, credit ledger/settlement and Marketplace/payout rules remain. Return/cancel handling still reconciles actual provider state; redirects grant nothing. An already created order retains its original provider-stored return URLs, including after deployment or env changes; do not create replacement orders for uncertain outcomes.
- Clerk already uses relative sign-in/sign-up, `/studio` completion and `/` sign-out URLs. Its test-key-only policy is preserved. Supabase is a server-only privileged Data API client with request-bound Clerk-to-`app_users` ownership; it does not use Supabase Auth redirects or a browser anon client. New Vercel checks reject a configured loopback database or legacy HTTP worker URL; local checks retain those options.
- The earlier Storyboard error was confirmed by the owner: Preview lacks the required V3 enable/owned-mode configuration. Local has both. No permission bypass/default change was made. Preview must receive the settings below and be redeployed.
- Read-only local audit found required current Clerk/DB/R2/PayPal/OpenAI/Higgsfield configuration present, Sandbox selected, and no forbidden public secret names. The laptop env files exist; their Supabase URL/key, R2 bucket and image/director model names match local configuration. No credential, account ID or hostname value was printed. Hosted values have not been inspected through a Vercel API.
